# Veil — 민감정보 가리기 / 되돌리기

CodeGate 2026 해커톤 프로젝트 VeilNote의 토큰화 엔진을 바탕으로 만든 스킬이다.
핵심 원칙은 VeilNote와 같다. **원문과 대응표는 사용자 컴퓨터에만 두고, AI는 토큰으로 가려진 글만 본다.**

```
원문 파일 ──veil──▶ 가린 파일 (Claude가 읽음) ──작업──▶ 토큰이 든 결과물 ──unveil──▶ 원문 복원 결과물
   └──────────────▶ 대응표 .veilmap.json (원문 포함, 로컬에만)
```

스크립트는 이 스킬 폴더의 `scripts/veil.mjs`에 있다 (Node 18+, 기본 기능은 외부 패키지 없음).
아래에서 `VEIL`은 `node "<이 스킬 폴더>/scripts/veil.mjs"`를 뜻한다.

## 먼저 판단할 것: 원문을 내가 이미 봤는가?

**A. 원문이 아직 파일로만 있다 (보호 모드)** — 사용자가 파일 경로를 줬고 내용은 대화에 없다.
이 경우가 이 스킬의 진짜 가치다. 원문을 읽지 않고 처리할 수 있으므로 아래 규칙을 지킨다.

- 원문 파일, `.veilmap.json`, `.unveiled.*` 파일은 Read/cat/grep 하지 않는다. 이 파일들을 읽는 순간 원문이 대화(=AI 서버)로 넘어가서 가린 의미가 사라진다.
- `--show`를 쓰지 않는다. 기본 출력은 `김**`처럼 첫 글자만 보이게 마스킹되어 있다.
- 사용자가 "그냥 원문 읽어도 돼"라고 하면 B로 진행해도 된다.

**B. 원문이 이미 대화에 있다 (붙여넣기 모드)** — 사용자가 글을 직접 붙여넣었다.
이미 본 글이므로 "AI에게서 숨기기"는 안 된다는 점을 한 줄로 솔직하게 알린다. 대신 가린 글을 다른 사람·다른 도구에 넘기거나, 일관된 토큰으로 정리하는 데는 그대로 쓸모가 있다.
글을 스크래치패드(없으면 작업 폴더)에 파일로 저장한 뒤 같은 명령을 쓰고, 검토할 때는 `--show`로 원문을 함께 보여줘도 된다.

## 작업 순서

### 1. 미리보기 (detect)

```bash
VEIL detect 회의록.txt
```

종류별로 몇 개가 잡혔는지, 어떤 근거로 잡혔는지 보여준다. 파일은 만들지 않는다.
`⚠ 확인 필요` 항목은 "성+두 글자+조사"처럼 약한 패턴으로 잡힌 것이라 일반 단어일 수도 있다.

- 보호 모드: 원문 값을 볼 수 없으므로 사용자에게 "확인 필요 N개가 있으니, 대응표(veil 이후 생성)를 열어 보고 가리지 않을 단어를 알려 달라"고 요청한다.
- 붙여넣기 모드: `--show`로 실제 값을 보여주고 사용자에게 확인받는다.
- 잘 안 잡히는 고유명사(신규 고객사명, 프로젝트 코드명, 직함 없이 나오는 이름)는 사용자에게 물어서 사전에 넣는다.
- 영어·유럽어·아랍어·중국어 문서이고 사람 이름·회사·지명까지 가려야 하면 `--ner`를 붙인다 (아래 "NER 모드").

### 2. 가리기 (veil)

```bash
VEIL veil 회의록.txt
VEIL veil 회의록.txt --dict dict.json --allow "법무팀,본사"
VEIL veil 1월.txt 2월.txt 3월.txt --map 프로젝트.veilmap.json   # 여러 파일 = 하나의 대응표
```

- 결과: `회의록.veiled.txt`(가린 글)와 `회의록.veilmap.json`(대응표).
- 같은 값은 문서 전체에서 같은 토큰이 된다. 한 번 사람 이름으로 잡히면 `김철수랑`처럼 패턴에 안 걸리는 곳도 함께 가려진다.
- 같은 대응표(`--map`)로 이어서 가리면 파일이 달라도 김철수는 계속 `[PERSON_1]`이다. 관련 문서 여러 개를 다룰 때는 하나의 대응표를 쓴다.
- 종료 코드 2와 `유출 검사: ⚠ 경고`가 나오면 가린 글에 원문이나 고위험 패턴이 남았다는 뜻이다. 대개 `--allow`나 `--skip-types`로 일부러 뺀 것이다. 의도한 것인지 사용자에게 확인하고, 아니면 고친 뒤 `--force`로 다시 실행한다.
- 다시 실행할 때는 기존 출력이 있으면 멈춘다. 덮어쓰려면 `--force`를 붙인다. 이때 대응표에는 항목이 이어서 쌓이므로, 처음부터 새로 하려면 사용자 확인 후 `.veilmap.json`을 지우고 실행한다.

사전 파일 예시 (`dict.json`). 종류 이름은 자유롭게 정할 수 있다:

```json
{ "ORG": ["한빛테크", "블루오션랩"], "PERSON": ["제임스 리"], "PROJECT": ["코드명 블루문"] }
```

### 3. 가린 글로 작업

`*.veiled.*` 파일만 Read로 읽고, 요청받은 작업(요약, 정리, 번역, 메일 초안, 표 만들기 등)을 한다. 결과물은 파일로 저장한다.

가린 파일을 읽다가 덜 가려진 민감정보(주소 일부, 사전에 없는 회사명, 직함 없이 나온 이름 등)가 보이면, 그 값을 사전(`--dict`)에 넣고 `--force`로 다시 가린 뒤 다시 읽는다. 이미 그 부분은 대화에 들어왔으므로, 무엇이 덜 가려졌었는지 마무리 보고 때 사용자에게 솔직하게 알린다.

토큰은 나중에 기계적으로 바꿔 넣을 자리이므로, 작업할 때 다음을 지킨다.

- 토큰을 `[PERSON_1]` 모양 그대로 쓴다. 대괄호를 빼거나, 번역하거나, `[사람1]`처럼 바꾸지 않는다.
- 토큰 뒤 조사(이/가, 은/는, 을/를, 과/와, 으로/로, 이랑/랑 등)는 아무 쪽이나 토큰에 바로 붙여 쓴다. unveil이 원문 마지막 글자의 받침을 보고 맞게 고친다 (`[PERSON_1]이` → `김철수가`). 원문이 영문이면 고치지 않으므로 그대로 둔다.
- 없는 토큰을 새로 만들지 않는다. 원문 값을 추측해서 적지 않는다.
- 토큰의 정체(성별, 직급 등)를 추측해서 덧붙이지 않는다. 원문에 있던 정보(예: `[PERSON_1] 팀장`)만 쓴다.

### 4. 되돌리기 (unveil)

```bash
VEIL unveil 요약.md --map 회의록.veilmap.json
```

- `요약.unveiled.md`가 생긴다. 보호 모드에서는 이 파일을 읽지 말고, 경로만 사용자에게 알려준다.
- `대응표에 없는 토큰` 경고: 결과물에 대응표에 없는 토큰이 있다는 뜻. 작업 중에 실수로 만든 것이므로 결과물을 고친다.
- `대괄호가 빠진 토큰` 경고: `PERSON_1`처럼 괄호가 빠진 곳이 있다. 결과물을 고치거나 `--loose`로 복원한다.

### 5. 마무리 보고

사용자에게 다음을 짧게 알린다.
- 무엇을 몇 개 가렸는지 (종류별 개수), 확인이 필요한 항목이 있었는지
- 만든 파일 경로: 가린 파일, 결과물, 복원된 결과물, 대응표
- 대응표에는 원문이 들어 있으니 공유하거나 깃에 올리지 말라는 안내 (필요하면 `.gitignore`에 `*.veilmap.json` 추가를 제안)

## 그 밖의 명령

```bash
VEIL check 보낼파일.md --map 회의록.veilmap.json   # 원문/고위험 패턴이 남았는지 검사 (종료 코드 2 = 남음)
VEIL types                                         # 탐지 종류 목록
VEIL --help
```

`check`는 가린 글을 외부로 보내기 직전에, 또는 작업 결과물에 원문이 섞여 들어가지 않았는지 볼 때 쓴다.

## 탐지 종류

기본으로 켜짐: `RRN`(주민·외국인등록번호), `SSN`(미국), `PASSPORT`, `SECRET`(비밀번호·API 키·토큰·계정 정보가 든 접속 주소), `EMPLOYEE_ID`(사번), `CARD`, `EMAIL`, `PHONE`, `ACCOUNT`(계좌·IBAN), `IP`(v4·v6), `ADDRESS`, `AMOUNT`(금액), `ORG`(회사·기관), `PERSON`(인명), `LOCATION`(지명, `--ner`에서만 나옴)

`SECRET`은 형식이 정해진 키(OpenAI `sk-…`, Anthropic `sk-ant-…`, GitHub `ghp_…`, AWS `AKIA…`, Slack, Stripe, JWT, 개인 키 블록 등), `비밀번호:`·`password=` 뒤의 값, `postgresql://user:pass@host` 같은 접속 주소 전체를 잡는다. 사전(`--dict`)에 넣은 값은 어떤 규칙보다 우선한다.
기본으로 꺼짐: `DATE`. 일정은 보통 작업에 필요해서 꺼 두었다. 필요하면 `--add-types DATE`로 켠다.
금액이 작업에 꼭 필요하면(예: 예산 합계 계산) `--skip-types AMOUNT`로 뺄 수 있다. 무엇을 남길지는 사용자에게 확인한다.

### 언어별로 규칙이 잡는 것

| | 한국어 | 영어 | 일본어 | 중국어 | 그 밖의 언어 |
|---|---|---|---|---|---|
| 이메일·IP·카드(체크섬)·IBAN·국제전화(+국가번호)·외화 금액 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 인명 | 성씨+직함/조사/`이고·이며·입니다`, `저는·담당자는·이름:` 뒤, `참석:` 목록 | `Mr./Dr.` + 이름, `CEO` + 이름, `Attendees:` 목록 | `〇〇さん/様/部長` | `〇〇先生/女士/经理` | `--ner` |
| 회사명 | ㈜, 주식회사, ~전자, `경쟁사 OO` | `Inc.`, `Ltd.`, `GmbH`, `~Labs` | 株式会社, ㈱ | 有限公司, 集团 | `--ner` |
| 주소 | 시·도·구·도로명 | 미국식 번지+거리, 영국 우편번호 | 〒, 都道府県 | 省·市·区·路·号 | `--ner`(지명) |
| 신분번호·전화 | 주민번호, 010·02 | SSN, 북미 전화 | 090 휴대폰 | — | 여권번호(“passport” 등 뒤) |

규칙은 정규식, 사전, 언어별 휴리스틱으로 동작한다. 완벽하지 않다. 직함 없이 나오는 이름이나 목록에 없는 회사명은 놓칠 수 있다. 그래서 1단계 미리보기와 사용자 사전이 중요하다. 정말 민감한 문서라면 놓친 게 있는지 사용자가 가린 파일을 한 번 훑어보게 권한다.

## NER 모드 (`--ner`, 선택)

로컬 개체명 인식 모델(`Xenova/bert-base-multilingual-cased-ner-hrl`)로 사람·회사·지명을 문맥으로 찾는다. 직함이 없는 이름(`Sarah said…`)이나 처음 보는 회사명(`Northwind`)처럼 규칙이 못 잡는 것을 채운다.

```bash
VEIL detect report.txt --ner
VEIL veil report.txt --ner
```

- 지원 언어: 영어, 독일어, 프랑스어, 스페인어, 이탈리아어, 포르투갈어, 네덜란드어, 라트비아어, 아랍어, 중국어. 한국어·일본어는 이 모델이 약하므로 규칙이 담당한다 (켜 둬도 해는 없다).
- 모델은 내 컴퓨터에서만 돈다. 첫 실행 때 Hugging Face에서 모델 파일(약 170MB)만 내려받고, 문서 내용은 어디에도 보내지 않는다. 캐시 위치는 `~/.cache/veil-models`.
- NER은 규칙이 놓친 빈자리만 채운다. 규칙이 이미 잡은 더 긴 덩어리(예: 주소 전체)를 NER이 쪼개지 않는다.
- `--ner-model <id>`로 다른 ONNX 토큰 분류 모델을 쓸 수 있다.

처음 쓸 때 `NER 모드에 필요한 패키지가 없습니다`라는 오류가 나면, 패키지 설치(약 480MB)와 모델 다운로드(약 170MB)가 필요하다는 점을 사용자에게 알리고 동의를 받은 뒤 스킬의 `scripts` 폴더에서 `npm install`을 실행한다. 사용자가 원하지 않으면 `--ner` 없이 규칙과 사전으로 진행한다.

## 지원 파일

UTF-8 또는 CP949(EUC-KR) 텍스트 파일: `.txt`, `.md`, `.csv`, `.json`, `.log` 등. 결과는 UTF-8로 저장한다.
`.docx`, `.pdf`, `.hwp`는 먼저 텍스트로 바꿔야 한다. 보호 모드라면 변환 결과가 대화에 출력되지 않는 방법(사용자가 직접 "다른 이름으로 저장 → 텍스트", 또는 `pandoc 파일.docx -o 파일.md`처럼 파일로만 쓰는 로컬 도구)을 쓴다. 내용을 화면에 돌려주는 변환 도구를 쓰면 원문이 대화로 들어온다.

## 이 스킬이 하지 않는 것

- 공부용 빈칸 문제 만들기(핵심어를 `____`로 바꾸기)는 목적이 다르다. 그 경우 이 스킬 없이 직접 만든다.
- 이미지나 스캔 문서 속 글자는 가리지 못한다.

## 동작 확인

```bash
node "<이 스킬 폴더>/scripts/selftest.mjs"          # 규칙·토큰화·복원
node "<이 스킬 폴더>/scripts/selftest.mjs" --ner    # + 실제 NER 모델
```
